# CLAUDE.md — правила работы над проектом «Рядом»

Проект: бесплатный сервис видеопомощи незрячим в РФ. Незрячий нажимает кнопку в Android-приложении, волонтёр отвечает по видео (с Android или из браузера).
Полная архитектура: `docs/ARCHITECTURE.md`. Контракт API: `docs/api/openapi.yaml`.

## Владелец проекта

Разработчик один, знает Kotlin и немного Python, код пишется с помощью Claude Code.
Объясняй решения коротко и по-русски, особенно в web (TypeScript) и инфраструктуре.
Перед крупными изменениями — короткий план и вопрос, если выбор неочевиден.

## Структура репозитория

```
backend/   Kotlin + Ktor, PostgreSQL (Flyway), Redis, LiveKit server SDK
shared/    Kotlin Multiplatform: API-клиент, WebSocket, авторизация, состояния запроса и звонка
android/   Kotlin + Jetpack Compose, LiveKit Android SDK, minSdk 26
ios/       (этап 11) SwiftUI поверх shared, LiveKit Swift SDK
web/       React + TypeScript (Vite): кабинет волонтёра и админка
infra/     docker-compose.yml, конфиг LiveKit, Caddy, скрипты деплоя
docs/      ARCHITECTURE.md, api/openapi.yaml, чек-листы тестирования
```

## Порядок работы

- Работаем по этапам из `docs/ARCHITECTURE.md`, раздел 13. Один этап — одна ветка и один PR.
- Сначала меняем `openapi.yaml`, потом код сервера и клиентов.
- Используй последние стабильные версии библиотек; версии Gradle — в version catalog (`libs.versions.toml`).
- Каждое изменение — с тестами; перед завершением этапа все тесты и линтеры должны проходить.
- Локальный запуск всего окружения: `docker compose -f infra/docker-compose.yml up`.

## Обязательные правила

1. **Доступность Android.** У каждого интерактивного элемента — описание для TalkBack; зоны нажатия от 48 dp; изменения статуса объявляются голосом; никакой информации только цветом. Новый экран без проверок доступности не считается готовым.
2. **Строки.** Весь пользовательский текст — через ресурсы, на русском и английском. Никаких строк в коде.
3. **Персональные данные.** Не собирать данные о здоровье и инвалидности, не записывать звонки, не хранить геолокацию. В логах — только id, без имён и токенов.
4. **Секреты.** Никаких ключей, паролей и токенов в репозитории. Только переменные окружения и секреты CI. Есть `.env.example` с пустыми значениями.
5. **Инфраструктура в РФ.** Не добавлять внешние сервисы на пути звонка (видео, сигнализация, БД). Исключение — push-каналы (FCM, RuStore, Web Push).
6. **Конфигурация.** Параметры подбора волонтёров (размер волн, интервалы, окно времени) — в конфиге, не в коде.
7. **Готовность к iOS.** Бизнес-логика — только в `shared`, без зависимостей от Android и LiveKit. В Android-коде — только UI, видео и платформенные API. Push на сервере — через общий интерфейс отправителя.
8. **Открытый код.** Комментарии и README понятны внешнему разработчику-волонтёру.
